# Nephalem Lab (research preview v0.3.2)

An **unofficial** Diablo III console item-seed and Kanai's Cube research tool.

## v0.3.2 — heading order and sockets

- Headings follow their physical order: 1 Game and item; 2 Target and recipe; 3 Seed recovery; 4 Candidate analysis, in English, Spanish and Portuguese.
- Socket counts, including **Sockets (3)** for Firebird's Breast, can now be recorded. Counts are not numerical seed-roll constraints; the analysis can only confirm the presence of a socket affix, not its exact count. No additional game materials are needed for this change.
- Stored item observations and compatible seeds use the same storage schema as v0.3.1. Create a backup before updating if data matters.

## Current release

- `universal.html`: **data-driven** engine. Loads the complete item/affix catalog used by D3Recipes (currently 692 items, 2,900 affixes) instead of hand-coding each item. Select any of the seven hero classes; predict reforges, primal improvement and sanctification, and simulate set conversion where applicable.
- `index.html`: the original, **experimentally confirmed Convention of Elements / Intelligence-class** proof of concept.
- Try inverse seed recovery on a normal, **unmodified** item's numerical affixes. Results are generated by integer constraints then replay-checked. It can report **no match**, **many candidates** or **one candidate**; not all objects reveal enough information. A single match is a candidate, not a game-tested guarantee.
- Seasonal constraints: default to season 40. Unverified/expired seasonal settings disable `Sanctify` (fail closed). Nonseasonal mode excludes it.
- Natural-primal search; optionally opt into crafted primals. The search is bounded and may fail to find a route even when one exists.
- English interface by default; Spanish and Portuguese UI available. Game item names and unrecognized affix families **fall back to their original English names**; comprehensive localized item-name tables are not yet available.

## Important limitations

1. **Not a finished universal seed cracker.** Generic formula inversion currently supports simple numerical rolls and unmodified normal initial observations. Exotic/nonnumeric powers, multi-attribute rolls and complex affix orderings require additional work. A unique result must be prospectively tested before trusting a costly route.
2. **Full item database downloads on first use** from a fixed D3Recipes commit. Internet is required for the first load; a browser cache stores a copy. Do not treat the season manifest as live-updating without a new verified release.
3. **Initial generic test vectors are synthetic fixtures** assembled from known game metadata and CoE ranges. They check different fixed-slot/roll layouts (Obsidian Ring of the Zodiac and Squirt's Necklace) but are not independent Switch 2 confirmations.
4. The Mystic check approximates legal target-family substitutions; it does not predict Mystic costs or how many rerolls will be required.
5. All calculations are for **Diablo III console** item-seed behavior as reverse-engineered by the community, not verified for PC.

## Local use

Requires Node 20+ only for the local server and tests. With Node:

```sh
npm test
npx http-server . -p 8080 -c-1
```

Then open `http://localhost:8080/universal.html` in your browser. Opening an HTML file directly with `file://` will not load web modules or workers correctly.

## Publish under a new GitHub repository

1. Create a **new repository** under your own account named `Nephalem-Lab` (prefer private during validation).
2. Upload the contents of this project directory, preserving the subfolders.
3. For GitHub Pages, enable **Settings → Pages → Source: GitHub Actions**; the included `pages.yml` publishes the site after a test run.
4. Visit `https://YOUR-USERNAME.github.io/Nephalem-Lab/universal.html` after GitHub reports the Pages deployment was successful.

**The GitHub connection available in this chat can modify existing repositories, but does not expose creation of a new repository. No repository was created or modified by this export.**

## Test policy

- Run `npm test` on every change (CI workflow included).
- The November 13, 2026 CoE proof is preserved as a regression test.
- For a **new live-console test**, choose a different item with several unmodified numerical affixes, preferably a ring or amulet with a different fixed-slot layout. Take a screenshot and record all values, including secondary affixes. If seed recovery is inconclusive, do not spend Forgotten Souls merely to force confirmation. Report limits honestly.

## Android APK (experimental)

The GitHub Actions workflow **Build Android APK** compiles an Android WebView shell
that loads the same `universal.html` and bundled JavaScript locally over Android's
`appassets.androidplatform.net` origin. It requires Internet only for the first
D3Recipes item database fetch. This is a **debug APK**, not Play Store-signed.

1. Go to **Actions → Build Android APK**.
2. Select the latest successful run (or click **Run workflow**).
3. Under **Artifacts**, download `Nephalem-Lab-Android-debug-APK`.
4. Extract the ZIP and open `Nephalem-Lab-debug.apk` on your Android phone.
5. Android may ask for permission to install apps from your file manager or browser.

The debug APK build must complete successfully before an installable APK exists.
For security, install only from the repository you control. The app does not modify
Diablo III or connect to Blizzard accounts.

## Candidate analysis (v0.3)

- **Candidate seeds persist locally** by item ID and hero class; a JSON copy/paste backup supports reinstalls or phone changes. An older app build did **not** save the 387 Firebird's Pinions seeds, so that 32-bit search must run **once more** after upgrading.
- After recovering multiple seeds, use **Analyze candidates** on `universal.html`. It simulates enabled operations for every retained seed, groups their *visible* tooltip outcomes, and compares expected/worst-case remaining candidates. These results are **conditional** on the inverse-model candidates, not certified game-state seeds.
- The information-efficiency ranking uses subjective relative weights (R=9, S=1, C=3, P=30), **not directly comparable material prices**. Never assume a cheap set conversion preserves the original item; it normally changes the set piece.
- **Current seasonal S** is available only if the season manifest says it is verified. Sanctified powers are not predicted; sanctified items are **not natural primals**.
- With target affixes selected, a **bounded** shared-path search explores at most 4 operations and 70 states. Failure does not imply no route exists, and an apparent shared route needs independent in-game confirmation.
- When entering a newly observed real R/S/P result, the saved candidate list is filtered and advanced without rescanning the 32-bit space. Record the **actual** operation and complete exact stats; never create a fake observation from a simulation. Set conversion now supports selecting and recording the new set piece and preserving the same candidate chain across conversions; it cannot directly produce Ancient/Primal.
- Initial Firebird's Pinions target defaults to Int + Vit + Cooldown Reduction + Resource Cost Reduction as a convenient experiment; confirm the exact desired build affixes before spending materials.

## Target-aware seed recovery and mixed set conversion (v0.3.1)

- Select the desired **final item and affix families before** beginning seed recovery. Those goals remain in the project while the current set piece changes.
- Candidate analysis ranks observable outcomes by approximate information gain **and limited goal-oriented lookahead**. Rankings are heuristic (not probabilities or absolute material prices); use actual resource budgets to decide whether to perform any recipe.
- **Convert Set Item** (C) costs **10 Forgotten Souls + 10 Death's Breaths**, requires at least three pieces in the set, and cannot itself give Ancient/Primal. It can be used between steps (for example C-C-R) if a future step returns to the selected final piece.
- After a real conversion, use `Resulting set piece` in the observation form and enter its actual stats. The candidate seeds advance and filter **without a new full seed search**, and the current item changes while the target remains fixed. If there is no match, the previous candidates are not overwritten.
- A common path is reported only if **every retained candidate** reaches the **exact target item** and natural primal quality with the requested affix families; Mystic refinement is not assumed in the shared-candidate shortcut. Candidate seeds are still experimental until independently confirmed.
- For a known single seed, the Dijkstra planner supports mixed R/S/C routes and includes C's materials in its displayed cost.
- The Android APK is version 0.3.1 research (`versionCode 3`). Existing v0.2 candidate lists were never saved; rerun the full scan once on the updated build, then use backup and restore.
